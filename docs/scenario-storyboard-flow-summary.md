## Overall Flow

**Target design: Category → Story Family → Narrative interaction → Decision → Result**

Runtime ปัจจุบันเลือก category แล้วเริ่ม template ที่กำหนดไว้ (Call Center เลือก internal variant ที่ Backend); ยังไม่มีหน้าเลือก 21 Story IDs. Generic non-SMS flow คือ `contact → build_trust → request_action → user_verification → end_scenario` ไม่ใช่หน้าจอ narrative ทุกภาพด้านล่าง.

เลือกหมวดและเรื่อง → เห็นบทบาทกับบริบทสมมติ → อ่านหลักฐานและพิมพ์โต้ตอบกับตัวละคร → เลือกตรวจสอบ ปฏิเสธ ยุติ หรือทำรายการจำลอง → อ่านผลและเหตุผลตามสิ่งที่พบจริง

ผู้เล่นไม่ใช่เพียงกดถัดไป: สามารถถาม เปิดหลักฐาน เลือกข้อมูลที่เห็นว่าควรตรวจเพิ่ม และใช้ช่องทางตรวจสอบที่แยกจากผู้ติดต่อได้ การดูข้อมูลไม่เท่ากับยอมทำตามคำขอ และการถามหรือขอเวลาตรวจไม่ถือเป็นการตัดสินใจผิด

ก่อนการกระทำเสี่ยงต้องเห็นสิ่งที่จะทำ ผู้รับหรือขอบเขตสิทธิ์ และคำยืนยันว่าเป็นการจำลอง พร้อมทางยกเลิก การพิมพ์หรือพูดคุยไม่ทำธุรกรรมแทนผู้เล่น ในโหมดเสียงต้องอ่านหรือฟังสรุปสิ่งที่จะยืนยันและแก้ข้อความที่ถอดเสียงคลาดเคลื่อนได้

**ความหมายของเส้นทาง:** Safe คือแนวทางระมัดระวัง; Review คือยอมรับข้อกล่าวอ้างจากหลักฐานที่ยังไม่เพียงพอ ไม่ใช่แค่คุยต่อ; Critical candidate คือเลือกเตรียมทำรายการเสี่ยงแต่ยังต้องยืนยันก่อน ทั้งหมดเป็นชื่อทางเลือกสำหรับคนวาด ไม่รับรองผลผ่านหรือไม่ผ่านตายตัว

แต่ละเรื่องข้ามไปผลลัพธ์ได้เมื่อเลือกยุติตามเงื่อนไขของเรื่อง ไม่ต้องเล่นถึงทุกขั้น ผลสะท้อนเฉพาะการตัดสินใจและข้อมูลที่พบในรอบนั้น รวมสิ่งที่ยังประเมินไม่ได้ การหยุดอย่างปลอดภัยไม่แปลว่าเชี่ยวชาญทั้งหมวด และไม่ลบการตัดสินใจก่อนหน้า หากเพียงปิดหรือพักการฝึกก่อนจบ ให้แสดงว่ายังฝึกไม่ครบ ไม่ให้ผลผ่านอัตโนมัติ

## 1. Call Center

**Matched controls:** CC-01 ↔ CC-N01 ใช้บริบทพัสดุ; CC-02 ↔ CC-N02 ใช้บริบทธนาคาร ผู้เล่นต้องสังเกตคำขอข้อมูลลับ/เงิน การยอมให้ตรวจอิสระ แรงกดดัน ความลับ และการวางสาย ไม่เดาจากอาชีพหรือชื่อหน่วยงาน

CC-N01 และ CC-N02 มีเรื่องย่อ 6 ภาพต่อเรื่อง ส่วนรายละเอียด 8 เฟรมเดิมอยู่ระดับ 2 ทั้งคู่ยังรออนุมัติ CC-N02 แบบธนาคารเป็นข้อเสนอ matched control ที่ต่อยอดจากแนวคิดสายปกติทั่วไป ไม่ใช่บทที่ต้นฉบับผู้ใช้ระบุไว้โดยตรง. การเลือก matched stories ในบริบทเดียวกันยังเป็นแผนอนาคต; แยกจาก runtime ที่สุ่ม NORMAL_CALL ห้องสมุด / SCAM_CALL ธนาคารปลอม 50/50 แล้ว

### CC-01 — คดีปลอมบังคับโอนเงินเพื่อตรวจสอบ

**Status:** CORE / NEEDS_CONTENT_REVIEW

**Mode:** TEXT_OR_VOICE

**เวลาประมาณ:** Text 4–6 นาที / Voice 6–9 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นรับสายจากผู้แอบอ้างเจ้าหน้าที่ ซึ่งใช้ข้อกล่าวหาและเอกสารสร้างความน่าเชื่อถือ ก่อนขอให้โอนเงินเพื่อตรวจสอบคดี

1. **สายเข้า:** หน้าจอแสดงผู้โทรที่อ้างว่าเป็นเจ้าหน้าที่ ผู้เล่นเลือกรับ พิมพ์ตอบหรือพูดคุยตามโหมด หรือวางสายตั้งแต่ต้นแล้วตรวจสอบผ่านช่องทางที่หาเองในระบบได้

2. **แจ้งข้อกล่าวหา:** ผู้โทรเริ่มจากเรื่องพัสดุแล้วอ้างว่าเกี่ยวข้องกับคดี ผู้เล่นขอรายละเอียด เลือกข้อมูลที่ควรตรวจเพิ่ม หรือยุติการติดต่อได้โดยไม่ต้องรับฟังจนจบ

3. **เสริมความน่าเชื่อถือ:** ผู้โทรให้เลขอ้างอิง ส่งเอกสารสมมติ หรือโอนสายไปยังผู้ที่อ้างตำแหน่งสูงกว่า ผู้เล่นเปิดดูและเปรียบเทียบข้อกล่าวอ้างได้ แต่เอกสารจากผู้โทรยังไม่ใช่ผลตรวจจากหน่วยงานอื่น

4. **เพิ่มแรงกดดัน:** อีกฝ่ายเร่งให้แก้ปัญหาทันทีและห้ามปรึกษาคนอื่น หากผู้เล่นยังเชื่อเอกสารโดยไม่ตรวจเพิ่ม จะพบคำขอให้โอนเงินเพื่อพิสูจน์ความบริสุทธิ์

5. **เลือกตรวจสอบ:** ผู้เล่นเลือกเปิดช่องทางหน่วยงานจำลองที่แยกจากผู้โทรเพื่อตรวจเลขคดีและขั้นตอน ปรึกษาบุคคลอื่น ปฏิเสธ หรือกลับมาคุยต่อได้ โดยการตรวจสอบไม่บังคับให้โอนเงินก่อน

6. **จุดตัดสินใจ:** ผู้เล่นเลือกหยุดติดต่อหรือทำตามคำขอโอน หากเลือกโอนเงิน ระบบแสดงยอดและผู้รับสมมติพร้อมหน้าต่างยืนยันว่าเป็นรายการจำลอง ผู้เล่นยกเลิกได้ก่อนดำเนินเรื่องต่อ

7. **ผลลัพธ์:** ระบบทบทวนเอกสาร การอ้างอำนาจ และแรงกดดันที่ผู้เล่นพบ พร้อมอธิบายผลของการตรวจสอบหรือทำรายการ และแนะนำการวางสายเพื่อติดต่อหน่วยงานเอง ผลสะท้อนเฉพาะเส้นทางที่เล่น ไม่สรุปว่าเชี่ยวชาญทั้งหมวด

**จุดตัดสินใจหลัก**
- ตรวจเลขคดีผ่านช่องทางที่หาเอง
- ปฏิเสธหรือยืนยันการโอนเงินจำลอง
- วางสายและขอคำปรึกษา

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: หยุดคำขอโอนและตรวจหน่วยงานอย่างอิสระ รวมถึงวางสายตั้งแต่ต้น
- Review: ยึดเอกสารหรือคำอ้างตำแหน่งเป็นข้อยืนยันทั้งที่ยังไม่ได้ตรวจเพิ่ม แล้วเผชิญแรงกดดันต่อ
- Critical candidate: เลือกโอนเงินตามข้อกล่าวหา ต้องผ่านหน้าต่างยืนยันรายการจำลองก่อน

**ภาพสำคัญสำหรับ Storyboard**
- หน้าจอสายเข้าและบทสนทนา
- เอกสารคดีสมมติและการโอนสาย
- หน้าตรวจช่องทางหน่วยงาน
- หน้าต่างยืนยันโอนเงินจำลอง
- หน้าสรุปการตัดสินใจ

### CC-02 — สายธนาคารปลอมขอรหัสยืนยัน

**Status:** DEMO / NEEDS_CONTENT_REVIEW

**Mode:** TEXT_OR_VOICE

**เวลาประมาณ:** Text 4–6 นาที / Voice 6–9 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นได้รับสายอ้างฝ่ายดูแลบัญชีธนาคาร ผู้โทรใช้เหตุธุรกรรมผิดปกติเพื่อขอรหัสยืนยันระหว่างสนทนา ไม่ใช่เรื่องลิงก์ไปกรอกแบบฟอร์ม

1. **สายแจ้งปัญหาบัญชี:** ผู้โทรอ้างว่าพบธุรกรรมผิดปกติและเสนอช่วยแก้ไข ผู้เล่นพิมพ์ตอบหรือพูดคุย ขอรายละเอียด หรือวางสายเพื่อตรวจด้วยตนเองได้ตั้งแต่ต้น

2. **แสดงข้อมูลประกอบ:** ผู้โทรอ้างข้อมูลบัญชีสมมติและเลขอ้างอิงเพื่อให้ดูน่าเชื่อถือ ผู้เล่นเปิดอ่านข้อความแจ้งเตือนที่เตรียมไว้และเลือกส่วนที่ต้องตรวจเพิ่มได้

3. **ขอรหัสยืนยัน:** อีกฝ่ายเร่งให้บอกรหัสที่ปรากฏในข้อความโดยอ้างว่าจะหยุดธุรกรรม ผู้เล่นเปรียบเทียบวัตถุประสงค์ของรหัสกับคำกล่าวอ้าง หรือปฏิเสธคำขอได้

4. **ตรวจจากช่องทางเดิม:** ผู้เล่นเลือกวางสายแล้วเปิดแอปธนาคารจำลองและช่องทางติดต่อที่มีอยู่เดิม เพื่อตรวจรายการ หากกลับไปเชื่อเพียงชื่อผู้โทร อีกฝ่ายยังขอให้แจ้งรหัสต่อ

5. **จุดตัดสินใจ:** ผู้เล่นเลือกเก็บรหัสไว้และหยุดติดต่อ หรือเลือกส่งรหัสสมมติ ระบบแสดงรหัสและการกระทำให้ตรวจทานก่อนยืนยันหรือยกเลิก ไม่รับรหัสจริงและไม่ส่งรหัสจากเครื่องผู้เล่น

6. **ผลลัพธ์:** ระบบอธิบายคำขอรหัสและความไม่สอดคล้องที่พบ ทบทวนว่าผู้เล่นตรวจรายการหรือเปิดเผยข้อมูลอย่างไร และแนะนำให้ตรวจผ่านแอปหรือช่องทางเดิมโดยไม่ใช้ชื่อผู้โทรเป็นหลักฐานเพียงอย่างเดียว

**จุดตัดสินใจหลัก**
- เปรียบเทียบวัตถุประสงค์ของรหัสกับคำอ้าง
- ตรวจรายการผ่านแอปที่เปิดเอง
- ปฏิเสธหรือยืนยันส่งรหัสสมมติ

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: เก็บรหัสไว้ วางสาย และตรวจรายการจากช่องทางเดิม
- Review: เชื่อชื่อธนาคารหรือเลขอ้างอิงเป็นข้อยืนยันโดยยังไม่ตรวจแหล่งอื่น
- Critical candidate: เลือกแจ้งรหัสสมมติแก่ผู้โทร โดยต้องตรวจทานและยืนยันก่อน

**ภาพสำคัญสำหรับ Storyboard**
- สายอ้างฝ่ายดูแลบัญชี
- ข้อความแจ้งวัตถุประสงค์ของรหัสสมมติ
- หน้ารายการในแอปธนาคารจำลอง
- หน้าตรวจทานการส่งรหัส
- หน้าผลลัพธ์

### CC-N01 — สายยืนยันการจัดส่งปกติ

**Status:** CONTROL / CONDITIONAL_CONTENT

**Mode:** TEXT_OR_VOICE

**เวลาประมาณ:** Text 3–4 นาที / Voice 4–5 นาที

**Matched scam:** CC-01 (parcel / delivery)

**แนวคิดของสถานการณ์:**
สายยืนยันจัดส่งปกติที่จับคู่กับ CC-01 ในบริบทพัสดุ ผู้เล่นตรวจคำสั่งซื้อเดิมและตอบเฉพาะเรื่องจัดส่ง โดยไม่มีการเปลี่ยนเรื่องเป็นคดีหรือคำขออันตราย

1. **สายจากผู้จัดส่ง:** ผู้เล่นได้รับสายเรื่องพัสดุและมีคำสั่งซื้อจำลองอยู่ก่อนแล้ว เลือกรับสาย วางสาย หรือเปิดคำสั่งซื้อเองได้ โดยยังไม่ทราบจากชื่อหน้าจอว่าสายเป็นประเภทใด

2. **แจ้งเลขพัสดุ:** ผู้โทรแจ้งเลขพัสดุและถามช่วงเวลาที่สะดวกรับสินค้า ผู้เล่นฟัง พิมพ์ถามหรือพูดตอบ ขอให้ทวน หรือเลือกตรวจเลขพัสดุก่อนได้

3. **เปรียบเทียบคำสั่งซื้อ:** ผู้เล่นเปิดประวัติการสั่งซื้อของตนเองแล้วตรวจเลขพัสดุ เวลา และร้านค้ากับสิ่งที่ได้รับแจ้ง ผู้โทรให้เวลาตรวจโดยไม่เร่งหรือห้ามวางสาย

4. **ตอบเฉพาะเรื่องจัดส่ง:** ข้อมูลตรงกับคำสั่งซื้อเดิมและผู้โทรขอเพียงเวลารับสินค้า ผู้เล่นเลือกยืนยันเวลา ขอเลื่อน หรือไม่ให้ข้อมูลเกินความจำเป็น โดยไม่มีคำขอรหัสลับหรือการจ่ายเงิน

5. **ทวนเวลาและจบสาย:** ผู้โทรทวนเวลาจัดส่งตามที่ตกลงแล้วจบสายตามปกติ ผู้เล่นรับทราบหรือจบสายได้ รวมถึงเลือกติดต่อกลับผ่านช่องทางที่มีอยู่เดิมโดยไม่ถูกกดดัน

6. **ผลลัพธ์:** ระบบสะท้อนการเทียบคำสั่งซื้อและขอบเขตข้อมูลที่ผู้เล่นตอบ การตรวจสอบอย่างสุภาพทำได้แม้เป็นการติดต่อที่ถูกต้อง ไม่แต่งสัญญาณเตือนหรือคำขออันตราย และไม่ถือว่าการรับสายหรือขอวางสายเป็นความผิด

**จุดตัดสินใจหลัก**
- เปิดคำสั่งซื้อเองเพื่อตรวจเลขพัสดุ เวลา และร้านค้า
- ตอบเฉพาะเวลารับสินค้าหรือขอเลื่อน
- วางสายและติดต่อกลับผ่านช่องทางเดิม

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจคำสั่งซื้อแล้วตอบเท่าที่จำเป็น หรือขอวางสายเพื่อตรวจภายหลัง
- Review: ยังไม่กำหนด ไม่ลงโทษการรับทราบ ความระมัดระวัง หรือการขอวางสาย
- Critical candidate: ไม่มีคำขอหรือการกระทำอันตรายในเรื่องนี้

**ภาพสำคัญสำหรับ Storyboard**
- สายเรื่องพัสดุและรายการสั่งซื้อเดิม

- ข้อความทวนเวลาและจบสาย
- หน้าสะท้อนการตรวจสอบ

### CC-N02 — สายธนาคารปกติแจ้งให้ตรวจสอบรายการ

**Status:** CONTROL / CONDITIONAL_CONTENT

**Mode:** TEXT_OR_VOICE

**เวลาประมาณ:** Text 3–4 นาที / Voice 4–5 นาที

**Matched scam:** CC-02 (bank / transaction)

**แนวคิดของสถานการณ์:**
สายธนาคารปกติที่จับคู่กับ CC-02 ในบริบทรายการธุรกรรม ผู้โทรให้ผู้เล่นตรวจผ่านแอปที่เปิดเองโดยไม่ขอข้อมูลลับหรือเงิน เป็นข้อเสนอ matched control ไม่ใช่แบบแผนการติดต่อของทุกธนาคาร

1. **สายแจ้งให้ตรวจรายการ:** ผู้เล่นได้รับสายจากฝ่ายธนาคารสมมติแจ้งว่ามีรายการที่ควรตรวจสอบ ผู้เล่นเลือกรับสาย ขอรายละเอียด หรือวางสายได้โดยไม่ต้องทำตามผู้โทรก่อน

2. **แจ้งข้อมูลอ้างอิงทั่วไป:** ผู้โทรบอกข้อมูลอ้างอิงของรายการสมมติ แต่ไม่ขอ OTP รหัสผ่าน หรือข้อมูลลับ ผู้เล่นฟัง พิมพ์ถามหรือพูดตอบ ขอให้ทวน หรือเตรียมตรวจด้วยตนเองได้

3. **เปิดช่องทางของตนเอง:** ผู้โทรแนะนำให้เปิดแอปธนาคารจำลองจากเมนูของผู้เล่น ไม่ส่งลิงก์ให้ทำรายการ ผู้เล่นเลือกเปิดแอปเองหรือวางสายก่อนตรวจได้ โดยผู้โทรยอมรับและไม่เร่งรัด

4. **เปรียบเทียบรายการ:** ผู้เล่นเทียบยอด เวลา และรายการในแอปกับข้อมูลที่ได้รับแจ้ง ข้อมูลอ้างอิงตรงกับรายการสมมติ ผู้เล่นตรวจเพิ่มผ่านช่องทางเดิมได้โดยไม่ต้องอ่านข้อมูลลับหรือรายละเอียดบัญชีกลับให้ผู้โทร

5. **รับทราบหรือติดต่อกลับ:** ผู้เล่นเลือกรับทราบ จบสาย หรือติดต่อธนาคารผ่านช่องทางที่บันทึกไว้เอง ผู้โทรยอมรับทางเลือกและจบการสนทนา ไม่มีคำขอโอนเงินหรือให้ดำเนินธุรกรรมผ่านสาย

6. **ผลลัพธ์:** ระบบทบทวนว่าผู้เล่นตรวจรายการจากช่องทางใดและรักษาข้อมูลอย่างไร แสดงว่าสายปกติในเรื่องนี้ยอมให้ตรวจเองโดยไม่ขอ OTP หรือให้โอนเงิน การขอวางสายไม่ใช่ความผิด และตัวอย่างจำลองนี้ไม่ใช่ข้อสรุปว่าธนาคารทุกแห่งต้องติดต่อในรูปแบบเดียวกัน

**จุดตัดสินใจหลัก**
- เปิดแอปธนาคารจำลองด้วยตนเอง
- ตรวจยอด เวลา และรายการโดยไม่เปิดเผยข้อมูลลับ
- รับทราบ วางสาย หรือติดต่อกลับผ่านช่องทางเดิม

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจรายการจากแอปที่เปิดเอง หรือวางสายแล้วติดต่อช่องทางธนาคารเดิม
- Review: ยังไม่กำหนด ไม่ลงโทษการรับทราบ ความระมัดระวัง หรือการขอวางสาย
- Critical candidate: ไม่มีคำขอหรือการกระทำอันตรายในเรื่องนี้

- ข้อมูลอ้างอิงทั่วไปในบทสนทนา
- เมนูเปิดแอปธนาคารจำลองเอง
- หน้าตรวจยอด เวลา และรายการ
- ตัวเลือกรับทราบ วางสาย หรือติดต่อกลับ
- หน้าสะท้อนการตรวจสอบ

### INV-01 — ลงทุนได้กำไรช่วงแรกแต่ถอนเงินติดค่าปลดล็อก

**Status:** DEMO / NEEDS_CONTENT_REVIEW

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นเห็นพอร์ตลงทุนและประวัติถอนเงินเล็กน้อยที่เรื่องเตรียมไว้ ก่อนถูกเรียกเงินเพิ่มเมื่อจะถอนก้อนใหญ่ เน้นแยกยอดที่แสดงออกจากการตรวจสอบผู้ให้บริการ

1. **ได้รับข้อเสนอ:** ผู้ดูแลกลุ่มชวนลงทุนและแสดงผลตอบแทนที่น่าสนใจ ผู้เล่นพิมพ์ถาม ตรวจข้อมูลเบื้องต้น หรือยุติการติดต่อได้ตั้งแต่ช่วงนี้

2. **สมาชิกช่วยรับรอง:** ในกลุ่มมีข้อความรับรองและภาพกำไรสมมติ ผู้เล่นเปิดดูและเลือกข้อมูลที่ควรตรวจเพิ่ม หรือเชื่อคำรับรองแล้วฟังข้อเสนอต่อ

3. **เห็นผลทดลองช่วงแรก:** ระบบแสดงประวัติทดลองลงทุนและถอนเงินเล็กน้อยเป็นบริบทที่เตรียมไว้ ผู้เล่นอ่านรายการได้ โดยประวัตินี้ไม่ใช่การโอนที่ผู้เล่นถูกบังคับให้ทำ

4. **ยอดกำไรเพิ่มขึ้น:** พอร์ตแสดงกำไรสูงและผู้ดูแลชวนเพิ่มทุน ผู้เล่นเลือกเปรียบเทียบยอดพอร์ตกับรายการเงินจำลองหรือถามเงื่อนไข แทนการตัดสินจากกราฟเพียงอย่างเดียว

5. **ถอนเงินติดขัด:** เมื่อเข้าสู่เหตุถอนก้อนใหญ่ ผู้ดูแลอ้างว่าต้องจ่ายค่าปลดล็อกก่อนและเร่งให้รักษาสิทธิ์ ผู้เล่นสามารถหยุดคำขอหรือขอรายละเอียดของค่าธรรมเนียมได้

6. **ตรวจที่มาและรายการเงิน:** ผู้เล่นเปิดทะเบียนผู้ให้บริการกับรายการเงินจากเมนูอิสระเพื่อตรวจชื่อและเงื่อนไข หากยังยึดกำไรหรือประวัติถอนเล็กน้อยเป็นหลัก อีกฝ่ายจะย้ำให้จ่ายเพิ่ม

7. **จุดตัดสินใจ:** ผู้เล่นเลือกหยุดเพิ่มทุนและเก็บหลักฐาน หรือทำรายการตามคำขอ ระบบให้ตรวจยอดและผู้รับ พร้อมยืนยันว่าเป็นการโอนเงินจำลองก่อนดำเนินการ และยกเลิกได้

8. **ผลลัพธ์:** ระบบเทียบหลักฐานที่ผู้เล่นใช้กับคำขอจ่ายเพิ่ม อธิบายว่ากำไรบนหน้าจอหรือการถอนได้ช่วงแรกยังไม่รับรองความน่าเชื่อถือ พร้อมสะท้อนการตรวจผู้ให้บริการและการหยุดจ่ายตามเส้นทางที่เล่น

**จุดตัดสินใจหลัก**
- ตรวจผู้ให้บริการและรายการเงินแยกจากกลุ่ม
- ไม่ใช้ผลตอบแทนช่วงแรกยืนยันความปลอดภัยทั้งหมด
- หยุดหรือยืนยันการโอนเงินจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: หยุดเพิ่มเงินและตรวจผู้ให้บริการกับรายการเงินอย่างอิสระ
- Review: ยึดรีวิว กราฟ หรือการถอนช่วงแรกเป็นข้อยืนยันแล้วรับแรงกดดันเพิ่ม
- Critical candidate: เลือกโอนเพิ่มหรือจ่ายค่าปลดล็อก ผ่านการยืนยันรายการจำลองก่อน

**ภาพสำคัญสำหรับ Storyboard**
- โฆษณาและกลุ่มลงทุน
- พอร์ตกับประวัติถอนเงินสมมติ
- ข้อความถอนเงินติดขัด
- หน้าตรวจทะเบียนและรายการเงิน
- หน้าตัดสินใจและยืนยันโอน
- หน้าผลลัพธ์

### INV-02 — ลงทุนที่ให้ผลตอบแทนจากการชวนสมาชิก

**Status:** CORE / CONDITIONAL_CONTENT

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นได้รับข้อเสนอธุรกิจที่รายได้ผูกกับการนำสมาชิกใหม่เข้าร่วม จุดสำคัญคือการตรวจแหล่งรายได้ ไม่ใช่ปัญหาถอนกำไรแบบ INV-01

1. **ข้อเสนอธุรกิจ:** ผู้ชักชวนนำเสนอการลงทุนและรายได้เสริม ผู้เล่นพิมพ์ถามเกี่ยวกับธุรกิจ เปิดแผนรายได้ หรือยุติการสนทนาได้ตั้งแต่ต้น

2. **อธิบายผลตอบแทน:** อีกฝ่ายแสดงตัวอย่างรายได้และเรื่องราวสมาชิก ผู้เล่นเลือกดูรายละเอียดว่าส่วนใดมาจากการขายหรือกิจกรรมทางธุรกิจ และส่วนใดมาจากสมาชิกใหม่

3. **โบนัสจากการชวนคน:** แผนแสดงว่ารางวัลเพิ่มตามจำนวนคนที่ชวน ผู้ชักชวนเน้นรายได้ส่วนนี้ ผู้เล่นตั้งคำถามหรือเลือกส่วนที่ควรตรวจเพิ่มได้

4. **เร่งให้เข้าร่วม:** ผู้ชักชวนเสนอให้ลงทุนและนำคนรู้จักเข้ามาเพื่อเพิ่มผลตอบแทน หากผู้เล่นยึดรายได้ของสมาชิกเป็นข้อยืนยัน อีกฝ่ายจะย้ำโอกาสที่อาจเสียไป

5. **ตรวจแหล่งรายได้:** ผู้เล่นเปิดข้อมูลธุรกิจและเงื่อนไขจากช่องทางอิสระในระบบ เทียบกับแผนสมาชิก แล้วเลือกถามต่อ ปรึกษาคนอื่น หรือหยุดก่อนนำผู้อื่นเข้ามา

6. **จุดตัดสินใจ:** ผู้เล่นเลือกปฏิเสธการลงทุนและการชวนคน หรือทำรายการลงทุนจำลองซึ่งต้องยืนยันยอดและผู้รับก่อน ไม่มีการเชิญคนจริง และไม่สรุปว่าการพูดถึงการชวนสมาชิกเป็นความผิดร้ายแรงโดยอัตโนมัติ

7. **ผลลัพธ์:** ระบบทบทวนว่าผู้เล่นตรวจที่มารายได้หรืออาศัยคำรับรองของสมาชิก อธิบายสัญญาณจากการพึ่งเงินสมาชิกใหม่และการเร่งตัดสินใจ พร้อมชี้เรื่องที่ยังต้องตรวจโดยไม่รับรองธุรกิจจากแผนรายได้เพียงชิ้นเดียว

**จุดตัดสินใจหลัก**
- แยกรายได้ธุรกิจออกจากเงินสมาชิกใหม่
- ตรวจเงื่อนไขก่อนลงทุนหรือชวนคน
- ปฏิเสธหรือยืนยันลงทุนจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจแหล่งรายได้และหยุดข้อเสนอที่ยังยืนยันไม่ได้
- Review: ถือแผนโบนัสหรือรายได้สมาชิกเป็นข้อรับรองทั้งที่ยังไม่ตรวจธุรกิจ
- Critical candidate: เลือกโอนเงินลงทุนจำลองและยืนยันก่อน โดยเกณฑ์การชวนคนยังรอทบทวนแยกต่างหาก

### ROM-01 — คนรักออนไลน์ขอเงินฉุกเฉิน

**Status:** DEMO / NEEDS_CONTENT_REVIEW

**Mode:** TEXT

**เวลาประมาณ:** Text 6–8 นาที

**แนวคิดของสถานการณ์:**
ตัวละครสร้างความผูกพันก่อนอ้างเหตุฉุกเฉินเพื่อขอเงิน ผู้เล่นฝึกแยกความห่วงใยออกจากการยืนยันเรื่องราวและการทำรายการทางการเงิน

1. **เริ่มรู้จัก:** ผู้เล่นเห็นโปรไฟล์สมมติและข้อความทักทาย สามารถพิมพ์ตอบ ตั้งขอบเขตข้อมูลส่วนตัว หรือจบการสนทนาได้โดยไม่ต้องสร้างความสัมพันธ์ต่อ

2. **หลายวันต่อมา:** ภาพข้ามเวลาแสดงการพูดคุยสม่ำเสมอและความสนิทที่เพิ่มขึ้น ผู้เล่นตรวจความสอดคล้องของเรื่องราวหรือเลือกหยุดได้ โดยไม่ต้องเล่นบทสนทนาจริงหลายวัน

3. **เกิดเหตุฉุกเฉิน:** ตัวละครอ้างปัญหาระหว่างเดินทางและส่งข้อมูลประกอบ ผู้เล่นเลือกส่วนที่ควรตรวจเพิ่ม ขอรายละเอียด หรือถามหาวิธียืนยันจากแหล่งอื่น

4. **ขอความช่วยเหลือเป็นเงิน:** อีกฝ่ายขอยืมเงินและหลีกเลี่ยงการตรวจสอบบางอย่าง ผู้เล่นเปรียบเทียบคำเล่ากับข้อมูลเดิม ปฏิเสธการจ่าย หรือคุยต่อเพื่อถามเหตุผลได้

5. **กดดันด้วยความสัมพันธ์:** หากผู้เล่นยังยึดความสนิทเป็นหลัก อีกฝ่ายกล่าวถึงความไว้ใจและความเร่งด่วน ผู้เล่นเลือกปรึกษาบุคคลอื่นหรือตรวจเหตุการณ์ผ่านช่องทางที่หาเองแทนการรีบจ่าย

6. **จุดตัดสินใจ:** ผู้เล่นเลือกปฏิเสธและยุติการติดต่อ หรือโอนเงินจำลอง โดยต้องตรวจยอด ผู้รับ และยืนยันก่อน ไม่มีการใช้เงินจริงและสามารถยกเลิกรายการได้

7. **ผลลัพธ์:** ระบบทบทวนความไม่สอดคล้อง คำขอเงิน และแรงกดดันทางอารมณ์ที่พบ แสดงผลของการรักษาขอบเขตและตรวจเหตุการณ์ โดยไม่ใช้สัญชาติ อาชีพ หรือความรู้สึกผูกพันเป็นคำตัดสินว่าบุคคลนั้นหลอกลวง

**จุดตัดสินใจหลัก**
- รักษาข้อมูลส่วนตัวและตรวจความสอดคล้อง
- ยืนยันเหตุฉุกเฉินนอกคำบอกเล่า
- ปฏิเสธหรือยืนยันโอนเงินจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: รักษาขอบเขต ตรวจเรื่องราว และปฏิเสธคำขอเงินที่ยังยืนยันไม่ได้
- Review: ถือความสนิทหรือคำสัญญาเป็นหลักฐานแล้วเผชิญแรงกดดันทางอารมณ์ต่อ
- Critical candidate: เลือกโอนเงินให้ตัวละครและผ่านการยืนยันรายการจำลอง

### ROM-02 — ของขวัญจากคนรักติดค่าธรรมเนียมปลอม

**Status:** CORE / NEEDS_CONTENT_REVIEW

**Mode:** TEXT

**เวลาประมาณ:** Text 6–8 นาที

**แนวคิดของสถานการณ์:**
ความสัมพันธ์ออนไลน์นำไปสู่ของขวัญที่อ้างว่าติดขั้นตอนจัดส่ง มีผู้ติดต่อคนที่สองเรียกค่าธรรมเนียม ผู้เล่นต้องตรวจเรื่องพัสดุแยกจากความไว้ใจคนรัก

1. **เริ่มความสัมพันธ์:** ตัวละครสมมติทักทายและคุยอย่างเป็นมิตร ผู้เล่นพิมพ์ตอบ จำกัดข้อมูลที่ให้ หรือเลือกจบการติดต่อได้ตั้งแต่ต้น

2. **หลายวันต่อมา:** ภาพข้ามเวลาสรุปความสัมพันธ์ที่ใกล้ชิดขึ้น ก่อนตัวละครบอกว่าจะส่งของขวัญ ผู้เล่นถามรายละเอียดหรือปฏิเสธของขวัญได้

3. **แสดงหลักฐานการส่ง:** ตัวละครส่งภาพของขวัญและข้อมูลจัดส่งสมมติ ผู้เล่นเปิดดูและเลือกตรวจเลขติดตาม โดยภาพที่อีกฝ่ายส่งไม่ใช่ผลยืนยันจากผู้ให้บริการ

4. **ผู้ติดต่อคนที่สอง:** บัญชีที่อ้างฝ่ายขนส่งแจ้งว่าพัสดุติดขั้นตอนและต้องจ่ายค่าธรรมเนียม ผู้เล่นเปรียบเทียบข้อมูลกับคำเล่าของคนรักหรือขอตรวจช่องทางขนส่งเอง

5. **ความกดดันเพิ่มขึ้น:** คนรักขอให้ช่วยรับของ ส่วนผู้ติดต่ออีกคนอ้างค่าใช้จ่ายเพิ่มเติมหรือเส้นตาย ผู้เล่นเลือกหยุดคำขอได้ ไม่ต้องจ่ายครั้งแรกเพื่อให้เห็นเหตุการณ์ถัดไป

6. **ตรวจพัสดุอย่างอิสระ:** ผู้เล่นเปิดช่องทางขนส่งจำลองที่หาเองเพื่อตรวจเลขพัสดุและเงื่อนไข แล้วเลือกข้อมูลที่น่าสงสัย หากเชื่อภาพของขวัญแทนการตรวจ อีกฝ่ายจะย้ำให้จ่าย

7. **จุดตัดสินใจ:** ผู้เล่นเลือกปฏิเสธค่าธรรมเนียมและหยุดติดต่อ หรือจ่ายในเรื่องจำลอง หน้าต่างให้ตรวจยอดและผู้รับ พร้อมยืนยันหรือยกเลิกก่อนดำเนินการ

8. **ผลลัพธ์:** ระบบเชื่อมข้อความของทั้งสองตัวละครกับข้อมูลพัสดุที่ผู้เล่นตรวจ อธิบายการใช้ความสัมพันธ์และค่าใช้จ่ายเพิ่มเป็นแรงกดดัน พร้อมแนะนำตรวจผู้ให้บริการแยกจากผู้ส่งของขวัญ

**จุดตัดสินใจหลัก**
- ตรวจพัสดุผ่านช่องทางที่หาเอง
- ไม่ใช้ความสัมพันธ์รับรองผู้เรียกเงิน
- หยุดหรือยืนยันค่าธรรมเนียมจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจการจัดส่งอย่างอิสระและปฏิเสธคำขอที่ยังยืนยันไม่ได้
- Review: เชื่อภาพของขวัญหรือคำรับรองคนรักจนยอมรับคำกล่าวอ้างเรื่องค่าธรรมเนียม
- Critical candidate: เลือกจ่ายค่ารับของขวัญและยืนยันรายการจำลองก่อน

- หน้าตรวจสถานะพัสดุ
- หน้าต่างยืนยันค่าธรรมเนียม
- หน้าผลลัพธ์

### ECO-01 — ร้านค้าชวนจ่ายนอกระบบแล้วไม่ส่งสินค้าตามตกลง

1. **พบสินค้าที่สนใจ:** ผู้เล่นเห็นสินค้า ราคา และหน้าร้านจำลอง สามารถเปิดดูรายละเอียด พิมพ์ถามผู้ขาย หรือยุติการซื้อได้ตั้งแต่ต้น

3. **ชวนออกนอกระบบ:** ผู้ขายเสนอส่วนลดเมื่อจ่ายตรงและอ้างว่าสินค้าใกล้หมด ผู้เล่นเลือกคงการซื้อในแพลตฟอร์ม ปฏิเสธ หรือคุยต่อโดยยังไม่จ่ายได้

4. **ตรวจช่องทางชำระ:** ผู้เล่นเปิดข้อมูลร้านและนโยบายคุ้มครองจากเมนูอิสระ เทียบชื่อผู้รับกับรายละเอียดร้าน หากยึดเพียงรีวิวหรือส่วนลด อีกฝ่ายจะเร่งให้โอนตรงต่อ

5. **จุดตัดสินใจ:** ผู้เล่นเลือกยุติการซื้อหรือใช้ช่องทางที่มีความคุ้มครอง หากเลือกโอนนอกระบบ ต้องตรวจผู้รับและยืนยันรายการจำลองก่อน โดยยกเลิกได้และไม่มีเงินจริง

6. **ผลลัพธ์:** ระบบแสดงผลตามทางที่เลือก รวมถึงปัญหาไม่ได้สินค้าตามตกลงในทางที่ทำรายการเสี่ยง ทบทวนการชวนออกนอกระบบ แรงเร่งซื้อ และหลักฐานร้าน พร้อมชี้วิธีตรวจเพิ่มก่อนชำระเงิน

**จุดตัดสินใจหลัก**
- ตรวจร้านมากกว่าดูรีวิว
- รักษาช่องทางคุ้มครองผู้ซื้อ
- ยุติการซื้อหรือยืนยันโอนจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจร้านและยุติคำขอจ่ายตรง หรือเลือกช่องทางที่มีความคุ้มครอง
- Review: เชื่อรีวิวหรือส่วนลดเป็นข้อรับรองโดยยังไม่ตรวจผู้ขายและเงื่อนไข
- Critical candidate: เลือกโอนนอกแพลตฟอร์มและยืนยันรายการจำลอง

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นเป็นผู้รับพัสดุที่จำไม่ได้ว่าสั่ง ต้องเทียบฉลากกับประวัติคำสั่งซื้อและคนในบ้านก่อนเลือกชำระเงินปลายทาง ไม่เหมารวมผู้จัดส่งว่าเป็นผู้หลอก

1. **พัสดุมาถึง:** ภาพหน้าบ้านและพัสดุสมมติแสดงชื่อผู้รับ ผู้เล่นเปิดดูฉลาก ขอรอเพื่อตรวจรายการ หรือปฏิเสธรับตั้งแต่ช่วงแรกได้

2. **จำคำสั่งซื้อไม่ได้:** ผู้เล่นเห็นว่ายังหาคำสั่งซื้อที่ตรงไม่พบ และผู้จัดส่งแจ้งยอดเก็บเงินปลายทาง ผู้เล่นพิมพ์ถามข้อมูลพัสดุได้โดยไม่ต้องจ่ายก่อน

3. **เทียบข้อมูลของตน:** ผู้เล่นตรวจประวัติคำสั่งซื้อและสอบถามคนในบ้านผ่านข้อมูลจำลอง แล้วเปรียบเทียบผู้ส่ง รายการ และยอด ไม่ใช้ชื่อบนกล่องเป็นหลักฐานว่าตนสั่ง

4. **พิจารณาคำขอเก็บเงิน:** เมื่ออีกฝ่ายขอคำตอบว่าจะรับหรือไม่ ผู้เล่นเลือกข้อมูลที่ยังไม่ตรง ขอพักการรับ หรือเชื่อฉลากแล้วพิจารณาจ่าย โดยไม่สรุปว่าผู้ส่งของร่วมหลอกลวง

5. **จุดตัดสินใจ:** ผู้เล่นเลือกปฏิเสธพัสดุที่ตรวจไม่ได้หรือยืนยันรับและจ่าย ระบบให้ตรวจยอดและยืนยันว่าชำระเงินปลายทางแบบจำลองก่อน สามารถยกเลิกได้

6. **ผลลัพธ์:** ระบบทบทวนความสัมพันธ์ระหว่างฉลาก คำสั่งซื้อ และคำตอบจากคนในบ้าน อธิบายผลของการรับหรือปฏิเสธ พร้อมแนะนำตรวจรายการก่อนจ่าย ไม่ใช้เพียงการจำไม่ได้เป็นข้อพิสูจน์ว่าพัสดุทุกชิ้นเป็นกลโกง

**จุดตัดสินใจหลัก**
- เทียบฉลากกับคำสั่งซื้อและคนในบ้าน
- พักหรือปฏิเสธการรับเมื่อยังตรวจไม่ได้
- ยืนยันชำระเงินปลายทางจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจคำสั่งซื้อและไม่จ่ายเมื่อยังยืนยันที่มาไม่ได้
- Review: ถือว่าชื่อผู้รับบนฉลากยืนยันการสั่งซื้อโดยยังไม่ตรวจรายการ
- Critical candidate: เลือกจ่ายค่าพัสดุที่ยังตรวจไม่ได้ ผ่านหน้ายืนยันจำลอง; เกณฑ์ผลร้ายแรงยังรออนุมัติ

### ECO-03 — ผู้ขายถูกหลอกด้วยหลักฐานชำระเงินปลอม

**Status:** CORE / CONDITIONAL_CONTENT

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นเป็นผู้ขายที่ได้รับสลิปจากผู้ซื้อและถูกเร่งให้ส่งสินค้า ต้องตรวจเงินเข้าผ่านช่องทางของร้านเองก่อนส่งมอบ ไม่ใช่ฝึกผู้ซื้อโอนเงิน

1. **ผู้ซื้อสั่งสินค้า:** หน้าร้านจำลองมีคำสั่งซื้อเข้ามา ผู้เล่นในบทผู้ขายพิมพ์คุย ตรวจรายละเอียดสินค้า หรือยุติการซื้อขายได้

2. **ส่งหลักฐานชำระเงิน:** ผู้ซื้อส่งภาพสลิปสมมติและอ้างว่าจ่ายแล้ว ผู้เล่นเปิดดูชื่อ ยอด และเวลา พร้อมเลือกส่วนที่ควรตรวจเพิ่มก่อนเตรียมส่ง

3. **เร่งให้ส่งของ:** ผู้ซื้อย้ำว่าต้องใช้สินค้าด่วนและให้ยึดสลิปเป็นหลัก ผู้เล่นเลือกชะลอการส่งหรือคุยต่อได้โดยยังไม่ส่งมอบสินค้า

4. **ตรวจเงินเข้าของร้าน:** ผู้เล่นเปิดรายการรับเงินจำลองของร้านเองและเทียบกับคำสั่งซื้อ หากยังไม่พบยอด ต้องตรวจสถานะต่อ ไม่สรุปจากความล่าช้าเพียงอย่างเดียวว่าสลิปปลอม

5. **จุดตัดสินใจ:** ผู้เล่นเลือกยังไม่ส่งจนยืนยันการรับเงินได้ หรือเลือกส่งสินค้าตามสลิป ระบบแสดงรายการสินค้าและหน้าต่างยืนยันการส่งมอบจำลองก่อนดำเนินเรื่อง ไม่มีการจัดส่งของจริง

6. **ผลลัพธ์:** ระบบเทียบสลิปกับรายการเงินที่ผู้เล่นตรวจ อธิบายผลของการส่งหรือชะลอสินค้าและการเร่งตัดสินใจ พร้อมแนะนำให้ยืนยันเงินเข้าจากช่องทางร้าน ไม่ใช้ภาพหลักฐานเพียงอย่างเดียว

**จุดตัดสินใจหลัก**
- ตรวจยอดรับเงินจากช่องทางร้าน
- ชะลอการส่งเมื่อยังไม่ยืนยันเงินเข้า
- ยืนยันส่งมอบสินค้าจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจยอดรับเงินจากรายการของร้านจำลองและยังไม่ส่งจนยืนยันได้
- Review: ถือสลิปเป็นหลักฐานเพียงพอทั้งที่ยังไม่เทียบรายการเงิน
- Critical candidate: เลือกส่งสินค้าตามหลักฐานที่ยังตรวจไม่ได้ ผ่านหน้ายืนยันจำลอง; เกณฑ์ส่งมอบยังรออนุมัติ

### PHI-01 — ข้อความพาไปแบบฟอร์มขโมยข้อมูล

**Status:** DEMO / NEEDS_CONTENT_REVIEW

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นได้รับข้อความอ้างบริการที่พาไปยังแบบฟอร์มขอข้อมูลลับ ฝึกตรวจผู้ส่งและปลายทางก่อนเปิดเผยข้อมูล ทุกลิงก์และแบบฟอร์มเป็นภาพจำลองในระบบ

1. **ได้รับข้อความ:** กล่องข้อความแสดงการแจ้งปัญหาบัญชี พัสดุ หรือสิทธิบริการสมมติ ผู้เล่นเลือกอ่าน พิมพ์ตอบ ไม่เปิดลิงก์ หรือยุติการติดต่อได้

2. **อ่านข้ออ้าง:** ข้อความเร่งให้ยืนยันข้อมูลก่อนหมดเวลาและแสดงชื่อผู้ส่งคล้ายบริการ ผู้เล่นเลือกข้อมูลที่ควรตรวจเพิ่ม ไม่ใช้ชื่อที่แสดงรับรองแหล่งที่มา

3. **ดูปลายทางล่วงหน้า:** ผู้เล่นเปิดภาพตัวอย่างลิงก์หรือ QR ในระบบได้โดยไม่เข้าเว็บไซต์ภายนอก หน้าตัวอย่างแสดงที่อยู่และชื่อบริการให้เปรียบเทียบ การดูภาพนี้ยังไม่ใช่การส่งข้อมูล

4. **พบแบบฟอร์ม:** หน้าเลียนแบบขอข้อมูลเข้าสู่ระบบหรือรหัสยืนยัน ผู้เล่นตรวจโดเมน วัตถุประสงค์แบบฟอร์ม และสิ่งที่ถูกขอ โดยโลโก้หรือ HTTPS เพียงอย่างเดียวไม่ยืนยันเจ้าของหน้า

5. **ตรวจบริการด้วยตนเอง:** ผู้เล่นเลือกเปิดช่องทางบริการจำลองจากเมนูที่แยกจากข้อความ หรือปิดหน้า หากเชื่อรูปลักษณ์เว็บไซต์โดยไม่ตรวจปลายทาง คำขอกรอกข้อมูลจะยังรออยู่

6. **จุดตัดสินใจ:** ผู้เล่นเลือกไม่ส่งข้อมูลและรายงานข้อความ หรือทดลองส่งข้อมูลสมมติที่ระบบเตรียมไว้ หน้าตรวจทานระบุข้อมูลที่จะส่งและให้ยืนยันหรือยกเลิก ไม่รับรหัสผ่านหรือรหัสจริง

7. **ผลลัพธ์:** ระบบชี้จุดที่ผู้เล่นพบในผู้ส่ง โดเมน และคำขอข้อมูล ทบทวนการเปิดดูแยกจากการส่งข้อมูล พร้อมแนะนำตรวจบริการผ่านช่องทางที่เปิดเองและเก็บข้อมูลลับไว้

**จุดตัดสินใจหลัก**
- ตรวจผู้ส่งและโดเมนปลายทาง
- เปิดช่องทางบริการด้วยตนเอง
- ปฏิเสธหรือยืนยันส่งข้อมูลสมมติ

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ไม่ส่งข้อมูล ตรวจผ่านช่องทางอิสระ และปิดหรือรายงานข้อความ
- Review: เชื่อชื่อ โลโก้ หรือหน้าตาเว็บเป็นข้อยืนยันโดยไม่ตรวจเจ้าของปลายทาง
- Critical candidate: เลือกส่งข้อมูลลับสมมติ ต้องผ่านหน้าตรวจทานและยืนยันก่อน

- แบบฟอร์มและโดเมนจำลอง
- ช่องทางบริการที่เปิดเอง
- หน้าตรวจทานข้อมูลและผลลัพธ์

### PHI-02 — ข้อความบริการปลอมพาไปติดตั้งแอป

**Status:** CORE / NEEDS_CONTENT_REVIEW

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ข้อความบริการชวนติดตั้งแอปเพื่อแก้ปัญหา ก่อนขอสิทธิ์ควบคุมอุปกรณ์ ผู้เล่นตรวจแหล่งแอปและความจำเป็นของสิทธิ์ผ่านหน้าจอจำลองที่ไม่ติดตั้งหรือเข้าถึงเครื่องจริง

1. **ข้อความชวนแก้ปัญหา:** ผู้เล่นได้รับข้อความอ้างบริการและลิงก์ติดตั้งแอป สามารถพิมพ์ถาม ปิดข้อความ หรือเลือกตรวจผู้ให้บริการก่อนเปิดดูแอปได้

2. **ดูแอปที่เสนอ:** หน้าตัวอย่างแสดงชื่อผู้เผยแพร่และคำอ้างว่าแอปช่วยจัดการบริการ ผู้เล่นตรวจแหล่งที่มาหรือเลือกดูขั้นติดตั้งจำลอง ซึ่งมีคำยืนยันก่อนและไม่ดาวน์โหลดไฟล์จริง

3. **พบคำขอสิทธิ์:** หน้าจอจำลองขอสิทธิ์เข้าถึงหรือควบคุมเครื่องเกินงานบริการ ผู้เล่นอ่านรายละเอียด เลือกสิทธิ์ที่ควรตรวจเพิ่ม หรือปฏิเสธได้โดยไม่มีการเปิดสิทธิ์อัตโนมัติ

4. **เร่งให้อนุญาต:** ผู้ติดต่ออ้างว่าต้องเปิดสิทธิ์จึงจะแก้ปัญหาได้ ผู้เล่นเลือกตรวจบริการและผู้เผยแพร่จากช่องทางที่หาเอง หรือกลับไปเชื่อคำอ้างว่าเป็นขั้นตอนปกติ

5. **จุดตัดสินใจ:** ผู้เล่นเลือกหยุดติดตั้งและไม่ให้สิทธิ์ หรือทดลองอนุญาตในภาพจำลอง ระบบแสดงขอบเขตสิทธิ์และขอคำยืนยันก่อน พร้อมให้ยกเลิก ไม่มีการควบคุมอุปกรณ์จริง

6. **ผลลัพธ์:** ระบบทบทวนแหล่งติดตั้ง สิทธิ์ที่ขอ และการเร่งให้ทำตาม อธิบายผลจากสิ่งที่ผู้เล่นเลือก พร้อมแนะนำตรวจบริการเองและไม่ให้สิทธิ์ที่ยังอธิบายความจำเป็นไม่ได้

**จุดตัดสินใจหลัก**
- ตรวจผู้เผยแพร่และช่องทางบริการ
- พิจารณาความจำเป็นของสิทธิ์
- หยุดหรือยืนยันการอนุญาตจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจแหล่งบริการและปฏิเสธการติดตั้งหรือสิทธิ์ที่ยังยืนยันไม่ได้
- Review: เชื่อชื่อแอปหรือคำอ้างขั้นตอนบริการแทนการตรวจแหล่งและสิทธิ์
- Critical candidate: เลือกให้สิทธิ์ควบคุมเครื่องในภาพจำลองหลังยืนยัน; เกณฑ์แยกการติดตั้งกับการให้สิทธิ์ยังต้องทบทวน

### TASK-01 — ทำภารกิจแล้วต้องเติมเงินเพื่อถอนค่าตอบแทน

**แนวคิดของสถานการณ์:**
ผู้เล่นทดลองงานง่ายและเห็นค่าตอบแทนเล็กน้อย ก่อนงานเปลี่ยนเป็นการสำรองเงินและจ่ายแก้รายการ จุดเน้นคือเงื่อนไขการทำงานและค่าจ้าง ไม่ใช่การลงทุน

1. **ได้รับงานง่าย:** ผู้ติดต่อเสนอรายได้จากภารกิจเกี่ยวกับสินค้า ผู้เล่นพิมพ์ถามที่มางาน ทดลองภารกิจตัวอย่าง หรือปฏิเสธข้อเสนอได้ตั้งแต่ต้น

2. **ทำภารกิจรอบแรก:** หน้าจอให้เลือกสินค้าในคำสั่งซื้อตัวอย่าง ผู้เล่นทดลองทำหรือหยุดได้ ภารกิจนี้เป็นการแสดงวิธีงาน ไม่ต้องใช้เงินจริงและไม่ใช่ข้อพิสูจน์ว่าผู้ว่าจ้างน่าเชื่อถือ

3. **ได้รับค่าตอบแทนเล็กน้อย:** รายการค่าจ้างสมมติแสดงรางวัลจากรอบแรกและคำชม ผู้เล่นตรวจรายการหรือถามเงื่อนไขงานถัดไปได้ แทนการยึดรางวัลเป็นหลักรับรองทั้งหมด

4. **งานเริ่มต้องใช้เงิน:** ผู้ติดต่อเสนองานระดับสูงที่ต้องสำรองเงินก่อน ผู้เล่นเห็นเงื่อนไขและประวัติยอดสำรองที่เรื่องเตรียมไว้เป็นบริบท ไม่บังคับให้โอนเพื่อเดินเรื่องต่อ

5. **ถอนค่าจ้างไม่ได้:** รายการงานแสดงยอดค้างและอีกฝ่ายอ้างว่าทำภารกิจผิด ต้องเติมเงินแก้ไข ผู้เล่นเปรียบเทียบงานที่ทำกับเหตุผลระงับค่าจ้างหรือขอหยุดได้

6. **ตรวจเงื่อนไขงาน:** ผู้เล่นเปิดข้อมูลผู้ว่าจ้างและรายการงานจากเมนูอิสระ เลือกสิ่งที่ควรตรวจเพิ่ม หากเชื่อค่าตอบแทนรอบแรกเป็นหลัก อีกฝ่ายจะเร่งให้จ่ายเพื่อเอายอดเดิมคืน

7. **จุดตัดสินใจ:** ผู้เล่นเลือกไม่สำรองหรือเติมเงินเพิ่มและเก็บหลักฐาน หรือเลือกจ่ายตามคำขอ ระบบแสดงรายการเติมเงินจำลองให้ยืนยันหรือยกเลิกก่อน ไม่มีธุรกรรมจริง

8. **ผลลัพธ์:** ระบบทบทวนจุดที่งานเปลี่ยนเป็นการจ่ายเงินและข้ออ้างระงับค่าจ้าง แสดงผลของการตรวจผู้ว่าจ้างและการหยุดเติม พร้อมอธิบายว่ารางวัลรอบแรกไม่รับรองงานทั้งหมด

**จุดตัดสินใจหลัก**
- ตรวจเงื่อนไขงานกับค่าจ้าง
- หยุดเมื่อถูกเรียกเงินเพื่อทำงานหรือถอนค่าตอบแทน
- ปฏิเสธหรือยืนยันเติมเงินจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจที่มางานและหยุดคำขอสำรองหรือเติมเงินเพิ่ม
- Review: ถือค่าตอบแทนรอบแรกเป็นข้อยืนยันแล้วเชื่อข้ออ้างแก้ภารกิจ
- Critical candidate: เลือกเติมเงินตามเงื่อนไขงานหรือแก้รายการ ผ่านการยืนยันจำลอง

## 7. Fake Loan

### LOAN-01 — สินเชื่ออนุมัติแต่ต้องจ่ายก่อนรับเงิน

**Status:** CORE / NEEDS_CONTENT_REVIEW

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นได้รับข้อเสนอสินเชื่อที่อ้างอนุมัติรวดเร็ว แต่ต้องจ่ายก่อนรับเงินและมีข้ออ้างเรียกเพิ่ม เน้นตรวจผู้ให้บริการและเงื่อนไขคำขอ ไม่รวมการให้สิทธิ์แอป

1. **พบข้อเสนอสินเชื่อ:** โฆษณาสมมติเสนออนุมัติง่าย ผู้เล่นอ่านเงื่อนไข พิมพ์ถามผู้ให้บริการ หรือยุติการติดต่อได้ตั้งแต่ต้น

2. **ดูใบสมัคร:** ระบบแสดงใบสมัครที่ใช้ข้อมูลสมมติเตรียมไว้ ผู้เล่นตรวจรายละเอียดหรือขอข้อมูลผู้ให้บริการเพิ่ม โดยไม่ต้องกรอกเอกสารหรือข้อมูลจริง

3. **แจ้งอนุมัติรวดเร็ว:** ผู้ติดต่อแสดงผลอนุมัติและยอดสินเชื่อ แต่ยังไม่มีเงินเข้าตามรายการ ผู้เล่นเทียบคำแจ้งกับเงื่อนไขในใบสมัครหรือขอตรวจผ่านช่องทางอื่น

4. **เรียกเงินก่อนรับสินเชื่อ:** อีกฝ่ายขอค่าดำเนินการหรือค่าประกันก่อนจ่ายเงินกู้ ผู้เล่นเลือกข้อมูลที่ควรตรวจเพิ่ม ปฏิเสธการจ่าย หรือถามเหตุผลได้

5. **อ้างปัญหาเพิ่มเติม:** ผู้ติดต่ออ้างข้อมูลผิดหรือมีขั้นตอนเพิ่มพร้อมเร่งให้จ่าย ผู้เล่นเปิดข้อมูลผู้ให้บริการและสถานะใบสมัครจากช่องทางอิสระเพื่อตรวจ ไม่ต้องจ่ายครั้งแรกเพื่อไปถึงขั้นนี้

6. **จุดตัดสินใจ:** ผู้เล่นเลือกหยุดคำขอที่ยังตรวจไม่ได้ หรือทำรายการชำระจำลอง ระบบให้ตรวจยอด ผู้รับ และยืนยันหรือยกเลิกก่อนดำเนินเรื่อง

7. **ผลลัพธ์:** ระบบทบทวนความต่างระหว่างคำอนุมัติกับสถานะใบสมัครและการเรียกเงินเพิ่ม แสดงผลของการตรวจผู้ให้บริการและการจ่าย พร้อมชี้ให้ตรวจเงื่อนไข ไม่ใช้การมีค่าธรรมเนียมเพียงอย่างเดียวตัดสินทุกบริการ

**จุดตัดสินใจหลัก**
- ตรวจผู้ให้บริการและสถานะใบสมัคร
- เทียบคำขอค่าธรรมเนียมกับเงื่อนไข
- หยุดหรือยืนยันชำระเงินจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจใบสมัครอย่างอิสระและไม่จ่ายคำขอที่ยังยืนยันไม่ได้
- Review: ถือผลอนุมัติหรือเอกสารจากผู้ติดต่อเป็นข้อยืนยันแล้วรับข้ออ้างเพิ่ม
- Critical candidate: เลือกจ่ายก่อนรับสินเชื่อผ่านการยืนยันรายการจำลอง

- หน้ายืนยันจ่ายและผลลัพธ์

### LOAN-02 — แอปเงินกู้ขอข้อมูลเครื่องและข่มขู่ผ่านคนใกล้ชิด

**Status:** DEMO / CONDITIONAL_CONTENT

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นพบแอปสินเชื่อที่ขอข้อมูลอุปกรณ์และรายชื่อผู้ติดต่อ ก่อนนำคำขู่เกี่ยวกับคนใกล้ชิดมากดดัน เน้นขอบเขตข้อมูล ไม่ใช่ค่าธรรมเนียมล่วงหน้า

1. **ข้อเสนอสินเชื่อผ่านแอป:** ผู้ติดต่อชวนสมัครผ่านแอปสมมติ ผู้เล่นพิมพ์ถาม ตรวจผู้ให้บริการ หรือยุติเรื่องได้ตั้งแต่ต้นโดยไม่ต้องติดตั้ง

2. **ดูแอปและคำขอเข้าถึง:** หน้าจอแสดงแอปและขั้นติดตั้งจำลองซึ่งต้องยืนยันก่อน จากนั้นผู้เล่นเปิดอ่านสิทธิ์ที่เกี่ยวกับการสมัครได้ ไม่มีไฟล์ติดตั้งหรือการเข้าถึงเครื่องจริง

3. **ขอข้อมูลเกินบริบท:** แอปขอรายชื่อผู้ติดต่อและข้อมูลอื่น ผู้เล่นเปรียบเทียบกับวัตถุประสงค์สินเชื่อ เลือกสิ่งที่ควรตรวจเพิ่ม และปฏิเสธสิทธิ์ที่อธิบายไม่ได้

4. **ผูกสิทธิ์กับการอนุมัติ:** ผู้ติดต่ออ้างว่าต้องยอมให้ข้อมูลจึงจะดำเนินการต่อ ผู้เล่นเลือกตรวจผู้ให้บริการกับเงื่อนไขความเป็นส่วนตัวจากช่องทางอิสระ แทนการยึดชื่อแอปหรือคำอนุมัติ

5. **ใช้คำขู่กดดัน:** อีกฝ่ายขู่ว่าจะติดต่อคนใกล้ชิดด้วยข้อมูลที่อ้างว่ามี ผู้เล่นเลือกเก็บข้อความ ขอความช่วยเหลือ หรือหยุดได้ รายชื่อที่ปรากฏเป็นข้อมูลแต่ง ไม่ได้ดึงจากโทรศัพท์ผู้เล่น

6. **จุดตัดสินใจ:** ผู้เล่นเลือกไม่ให้ข้อมูลและยุติการติดต่อ หรือทดลองอนุญาตสิทธิ์ในเรื่อง ระบบให้ตรวจรายการข้อมูลสมมติและยืนยันหรือยกเลิกก่อน โดยไม่มีการส่งรายชื่อจริง

7. **ผลลัพธ์:** ระบบอธิบายความไม่สัมพันธ์ของสิทธิ์กับงานสินเชื่อและการใช้คำขู่ แสดงผลของการรักษาข้อมูลและตรวจผู้ให้บริการ พร้อมแนะนำเก็บหลักฐานและขอความช่วยเหลือโดยไม่กล่าวโทษผู้เล่น

**จุดตัดสินใจหลัก**
- ตรวจความจำเป็นของสิทธิ์และผู้ให้บริการ
- รักษาข้อมูลของตนและคนใกล้ชิด
- หยุดหรือยืนยันการอนุญาตจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ปฏิเสธสิทธิ์ที่ยังอธิบายไม่ได้ เก็บหลักฐาน และตรวจช่องทางช่วยเหลือ
- Review: ถือการอนุมัติสินเชื่อเป็นเหตุให้ยอมรับว่าต้องขอข้อมูลทั้งหมด
- Critical candidate: เลือกให้ข้อมูลรายชื่อในเรื่องหลังยืนยันจำลอง; เกณฑ์ความร้ายแรงยังรออนุมัติ

- รายการสิทธิ์และข้อมูลที่ร้องขอ
- ข้อความเงื่อนไขอนุมัติ
- คำขู่กับรายชื่อแต่ง
- หน้าตัดสินใจและยืนยันสิทธิ์
- หน้าผลลัพธ์

## 8. Recovery

<a id="rec-01"></a>

### REC-01 — ตามเงินคืนแต่เรียกค่าดำเนินการเพิ่ม

**Status:** CORE / NEEDS_CONTENT_REVIEW

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นมีเหตุสูญเสียสมมติอยู่ก่อนแล้ว และมีผู้ติดต่ออ้างช่วยตามเงินคืนแต่ต้องจ่ายเพิ่ม ฝึกตรวจตัวผู้ช่วยและช่องทางเดิมโดยไม่ซ้ำเติมผู้เสียหาย

1. **เหตุเสียหายเดิม:** หน้าบริบทแสดงประวัติสูญเสียและหลักฐานสมมติที่เตรียมไว้ ผู้เล่นอ่านข้อมูลก่อนเริ่ม ไม่ต้องเล่าประสบการณ์จริงหรือทำรายการเสียหายใหม่

2. **ผู้ช่วยติดต่อมา:** ตัวละครอ้างรู้เรื่องและช่วยตามเงินได้ ผู้เล่นพิมพ์ถามที่มา ปฏิเสธ หรือจบการติดต่อแล้วไปใช้ช่องทางเดิมได้

3. **แสดงเอกสารรับรอง:** ผู้ติดต่อส่งเลขคดีหรือเอกสารสมมติ ผู้เล่นเลือกส่วนที่ต้องตรวจเพิ่ม โดยการรู้ข้อมูลเดิมยังไม่ยืนยันว่าเป็นผู้รับผิดชอบคดีจริง

4. **รับประกันได้เงินคืน:** อีกฝ่ายสร้างความหวังและขอค่าดำเนินการก่อน ผู้เล่นขอดูเงื่อนไข ตรวจผู้ติดต่อ หรือปฏิเสธคำขอได้

5. **เร่งให้รักษาโอกาส:** หากยังเชื่อคำรับประกัน อีกฝ่ายอ้างขั้นตอนเพิ่มและเวลาจำกัด ผู้เล่นเลือกเปิดประวัติแจ้งเหตุและช่องทางธนาคารหรือหน่วยช่วยเหลือที่หาเองเพื่อตรวจผู้ดำเนินการ

6. **จุดตัดสินใจ:** ผู้เล่นเลือกหยุดจ่าย เก็บหลักฐาน และใช้ช่องทางที่ตรวจแล้ว หรือชำระค่าติดตามจำลอง ระบบให้ยืนยันยอดและผู้รับก่อน พร้อมทางยกเลิก

7. **ผลลัพธ์:** ระบบทบทวนคำรับประกัน เอกสาร และการเรียกเงินเพิ่มที่พบ อธิบายผลของการตรวจผู้ช่วยและคำขอจ่าย พร้อมแนะนำช่องทางตอบสนองต่อเหตุเดิมโดยไม่ตำหนิผู้ที่เคยเสียหาย

**จุดตัดสินใจหลัก**
- ตรวจผู้ดำเนินการผ่านช่องทางเดิม
- ไม่ใช้การรู้ข้อมูลเหตุเดิมรับรองตัวตน
- หยุดหรือยืนยันค่าติดตามจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจผู้ช่วย เก็บหลักฐาน และหยุดคำขอจ่ายที่ยังยืนยันไม่ได้
- Review: ถือเอกสารหรือคำรับประกันคืนเงินเป็นข้อยืนยันแล้วรับแรงเร่งต่อ
- Critical candidate: เลือกจ่ายค่าติดตามเงินคืนและยืนยันรายการจำลอง

**ภาพสำคัญสำหรับ Storyboard**

### REC-02 — แอปแจ้งความหรือช่วยเงินคืนที่ขอควบคุมเครื่อง

**Status:** DEMO / CONDITIONAL_CONTENT

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
หลังเหตุสูญเสียสมมติ ผู้ติดต่ออ้างช่วยแจ้งความหรือคืนเงินผ่านแอปที่ขอควบคุมเครื่อง เรื่องนี้ยังเป็นเนื้อหาแบบมีเงื่อนไข ไม่ใช่บริการทั่วไปแบบ PHI-02

1. **เริ่มจากเหตุเดิม:** ผู้เล่นเห็นหลักฐานเหตุเสียหายสมมติและข้อความจากผู้เสนอช่วย สามารถพิมพ์ถามหรือยุติการติดต่อแล้วเปิดช่องทางแจ้งเหตุเองได้

2. **แนะนำขั้นตอนช่วยเหลือ:** ผู้ติดต่อแสดงคู่มือหรือข้อมูลรับเรื่องและเสนอให้ใช้แอป ผู้เล่นเทียบกับประวัติเดิมและเลือกข้อมูลที่ควรตรวจเพิ่ม ไม่ถือว่ารู้เรื่องเดิมแล้วเชื่อได้ทันที

3. **เสนอแอปช่วยจากระยะไกล:** หน้าตัวอย่างอ้างว่าแอปจะช่วยดำเนินเรื่อง ผู้เล่นเลือกดูขั้นติดตั้งจำลองที่ต้องยืนยันก่อน หรือปฏิเสธ โดยไม่มีโปรแกรมจริงถูกติดตั้ง

4. **ขอควบคุมเครื่อง:** ผู้ติดต่อเร่งให้เปิดสิทธิ์เพื่อช่วยต่อ ผู้เล่นอ่านขอบเขตสิทธิ์และเปิดช่องทางแจ้งเหตุจำลองที่หาเองเพื่อตรวจขั้นตอน พร้อมเก็บหลักฐานเดิมได้โดยไม่ส่งการควบคุมเครื่อง

5. **จุดตัดสินใจ:** ผู้เล่นเลือกไม่ให้สิทธิ์และหยุดติดต่อ หรือทดลองอนุญาตการควบคุมในเรื่อง หน้าต่างระบุขอบเขตและขอคำยืนยันหรือยกเลิก ไม่มีการเข้าถึงอุปกรณ์จริง

6. **ผลลัพธ์:** ระบบทบทวนการใช้ความหวังจากเหตุเดิมมาเชื่อมกับคำขอควบคุมเครื่อง อธิบายสิ่งที่ผู้เล่นตรวจและเลือก พร้อมแนะนำเก็บหลักฐานและยืนยันผู้รับเรื่องผ่านช่องทางอิสระ

**จุดตัดสินใจหลัก**
- ตรวจขั้นตอนและผู้รับแจ้งเหตุจากช่องทางอิสระ
- เก็บหลักฐานโดยไม่ให้สิทธิ์เครื่อง
- ปฏิเสธหรือยืนยันการควบคุมจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจช่องทางช่วยเหลือและปฏิเสธการควบคุมอุปกรณ์
- Review: เชื่อชื่อบริการช่วยเหลือหรือข้อมูลคดีเป็นข้อรับรองแอปโดยยังไม่ตรวจ
- Critical candidate: เลือกเปิดสิทธิ์ควบคุมในเรื่องผ่านการยืนยันจำลอง; เนื้อหายังคง CONDITIONAL_CONTENT

### JOB-01 — งานปลอมเรียกค่าสมัครหรือค่าอบรม

**Status:** DEMO / NEEDS_CONTENT_REVIEW

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้เล่นสมัครงานกับผู้ที่อ้างเป็นฝ่ายบุคคล ก่อนถูกเรียกค่าสมัคร ค่าอบรม หรือค่าอุปกรณ์เพื่อเริ่มงาน เน้นตรวจตำแหน่งและนโยบายค่าใช้จ่ายกับองค์กร

1. **พบประกาศงาน:** ประกาศสมมติเสนอรายได้และเงื่อนไขน่าสนใจ ผู้เล่นอ่านหน้าที่งาน พิมพ์ถามฝ่ายบุคคล หรือเลือกไม่สมัครได้ตั้งแต่ต้น

2. **รับเข้าทำงานรวดเร็ว:** หลังการพูดคุยสั้น ๆ ผู้ติดต่อแจ้งว่าผ่านและส่งข้อมูลบริษัท ผู้เล่นขอรายละเอียดตำแหน่งหรือเลือกสิ่งที่ต้องตรวจเพิ่ม โดยความรวดเร็วเพียงอย่างเดียวไม่ใช่ข้อสรุปว่าหลอก

3. **เรียกค่าใช้จ่ายก่อนเริ่ม:** อีกฝ่ายขอค่าอบรมหรืออุปกรณ์และเร่งให้จองสิทธิ์ ผู้เล่นปฏิเสธการจ่าย ถามเงื่อนไข หรือขอเวลาตรวจองค์กรได้

4. **ตรวจตำแหน่งกับองค์กร:** ผู้เล่นเปิดประกาศและช่องทางฝ่ายบุคคลจำลองที่หาเอง เทียบรหัสงาน ผู้รับสมัคร และนโยบายค่าใช้จ่าย หากยังเชื่อใบตอบรับอย่างเดียว อีกฝ่ายจะย้ำให้จ่าย

5. **จุดตัดสินใจ:** ผู้เล่นเลือกหยุดสมัครเมื่อยังตรวจไม่ได้ หรือชำระค่าใช้จ่ายตามคำขอ ระบบแสดงยอด ผู้รับ และหน้าต่างยืนยันการชำระจำลองก่อน โดยยกเลิกได้

6. **ผลลัพธ์:** ระบบทบทวนคำเรียกเงิน ความเร่งด่วน และข้อมูลตำแหน่งที่ผู้เล่นตรวจ อธิบายผลของการจ่ายหรือหยุด พร้อมแนะนำยืนยันงานกับองค์กร ไม่ตัดสินจากรูปแบบสัมภาษณ์หรือชื่อบริษัทเพียงอย่างเดียว

**จุดตัดสินใจหลัก**
- ตรวจตำแหน่งและฝ่ายบุคคลจากแหล่งอิสระ
- เทียบค่าใช้จ่ายกับนโยบายองค์กร
- หยุดหรือยืนยันจ่ายจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจตำแหน่งและหยุดคำขอจ่ายที่ยังยืนยันไม่ได้
- Review: เชื่อใบตอบรับหรือชื่อบริษัทเป็นข้อยืนยันโดยไม่ตรวจนโยบายค่าใช้จ่าย
- Critical candidate: เลือกจ่ายค่าเริ่มงานผ่านหน้าต่างยืนยันรายการจำลอง

**ภาพสำคัญสำหรับ Storyboard**

- หน้าตรวจตำแหน่งกับองค์กร

### JOB-02 — รับสมัครงานเพื่อเก็บเอกสารเกินจำเป็น

**Status:** EXTENDED / CONDITIONAL_CONTENT

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
ผู้รับสมัครอ้างเหตุคัดเลือกงานเพื่อขอเอกสารสำคัญเกินบริบท ผู้เล่นตรวจผู้รับและความจำเป็นของข้อมูลโดยไม่มีประเด็นจ่ายค่าสมัครหรือรับส่งเงิน

1. **พบงานและผู้รับสมัคร:** ผู้เล่นอ่านตำแหน่งสมมติและพิมพ์ถามผู้ติดต่อ เลือกตรวจองค์กรหรือหยุดได้ก่อนส่งข้อมูล

2. **เริ่มสมัครด้วยข้อมูลตัวอย่าง:** หน้าจอแสดงประวัติสมัครที่ใช้ข้อมูลแต่ง ผู้เล่นตรวจรายละเอียดและขอรายการเอกสารที่จำเป็นได้ ไม่ต้องอัปโหลดประวัติหรือเอกสารจริง

3. **ขอเอกสารสำคัญ:** ผู้รับสมัครส่งรายการเอกสาร ผู้เล่นเปิดดูชุดตัวอย่างและเลือกข้อมูลที่ควรตรวจเพิ่ม โดยยังไม่ส่งเอกสารทันทีที่เปิดดู

4. **ขอเพิ่มเกินบริบท:** อีกฝ่ายขอข้อมูลเพิ่มโดยอธิบายวัตถุประสงค์ไม่ชัดและเร่งให้ส่งครบ ผู้เล่นถามเหตุผล ปฏิเสธบางรายการ หรือหยุดการสมัครได้

5. **ตรวจความจำเป็น:** ผู้เล่นเปิดช่องทางฝ่ายบุคคลและข้อกำหนดเอกสารจากแหล่งอิสระ เทียบขั้นสมัคร ผู้รับ และข้อมูลที่จำเป็น ไม่ถือว่าการมีแบบฟอร์มยืนยันองค์กรแล้ว

6. **จุดตัดสินใจ:** ผู้เล่นเลือกยังไม่ส่งข้อมูลที่ตรวจไม่ได้ หรือเลือกส่งชุดเอกสารสมมติ ระบบแสดงรายการข้อมูลและผู้รับให้ตรวจทานก่อนยืนยันการส่งจำลองหรือยกเลิก ไม่มีการอัปโหลดไฟล์จริง

7. **ผลลัพธ์:** ระบบทบทวนความไม่สัมพันธ์ของข้อมูลกับขั้นสมัครและผลของการเปิดเผย อธิบายสิ่งที่ตรวจแล้วและสิ่งที่ควรถามเพิ่ม โดยไม่สรุปว่าการขอเอกสารสมัครงานทุกกรณีเป็นการหลอก

**จุดตัดสินใจหลัก**
- ตรวจองค์กรและผู้รับเอกสาร
- แยกข้อมูลจำเป็นออกจากข้อมูลเกินบริบท
- ระงับหรือยืนยันส่งชุดข้อมูลสมมติ

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ตรวจผู้รับและความจำเป็นก่อนส่ง พร้อมระงับข้อมูลที่ยังยืนยันไม่ได้
- Review: เชื่อแบบฟอร์มหรือชื่อฝ่ายบุคคลเป็นข้อรับรองการขอข้อมูลทั้งหมด
- Critical candidate: เลือกส่งชุดข้อมูลสมมติเกินจำเป็นหลังยืนยัน; เกณฑ์ชุดข้อมูลยังรอทบทวน

**ภาพสำคัญสำหรับ Storyboard**

- แชตขอข้อมูลเพิ่ม
- ข้อกำหนดเอกสารจากช่องทางอิสระ
- หน้าตรวจทานการส่งและผลลัพธ์

### JOB-03 — งานรับและส่งต่อเงินผ่านบัญชีส่วนตัว

**Status:** CORE / NEEDS_CONTENT_REVIEW

**Mode:** TEXT

**เวลาประมาณ:** Text 4–6 นาที

**แนวคิดของสถานการณ์:**
งานธุรการหรือการเงินถูกใช้ชวนผู้เล่นให้ใช้บัญชีส่วนตัวเป็นทางผ่านของเงิน ฝึกตรวจหน้าที่งาน เจ้าของเงิน และช่องทางธุรกรรมขององค์กร

1. **พบงานธุรการการเงิน:** ประกาศสมมติเสนอรายได้จากงานจัดการรายการ ผู้เล่นพิมพ์ถามหน้าที่ ตรวจองค์กร หรือยุติการติดต่อได้ตั้งแต่ต้น

2. **อธิบายหน้าที่:** ผู้ติดต่อบอกว่าเพียงรับยอดและส่งต่อก็ได้รับค่าตอบแทน ผู้เล่นขอรายละเอียดเจ้าของเงินและระบบของบริษัท หรือเลือกข้อมูลที่ควรตรวจเพิ่ม

3. **ขอใช้บัญชีส่วนตัว:** อีกฝ่ายอ้างความสะดวกและขอให้ใช้บัญชีผู้สมัครแทนบัญชีองค์กร ผู้เล่นปฏิเสธข้อเสนอนี้หรือตรวจเหตุผลได้โดยไม่ต้องให้ข้อมูลบัญชีจริง

4. **เห็นรายการรับส่ง:** หน้าจอแสดงตัวอย่างรายการและยอดรับที่เรื่องเตรียมไว้เป็นบริบท ผู้ติดต่อเร่งให้ส่งต่อ ยอดตั้งต้นไม่ใช่การรับเงินที่ผู้เล่นถูกบังคับให้ทำ

5. **ตรวจหน้าที่กับที่มาของเงิน:** ผู้เล่นเปิดข้อมูลบริษัทและประกาศจากช่องทางที่หาเอง เทียบหน้าที่ เจ้าของเงิน และช่องทางธุรกรรม หากเชื่อเพียงคำว่าบริษัทรับผิดชอบ อีกฝ่ายจะย้ำให้ทำตาม

6. **จุดตัดสินใจ:** ผู้เล่นเลือกไม่ให้ใช้บัญชีและหยุดส่งต่อ หรือเลือกส่งต่อเงินในเรื่อง ระบบให้ตรวจบัญชีสมมติ ยอด และผู้รับก่อนยืนยันการส่งต่อจำลองหรือยกเลิก ไม่มีการเชื่อมบัญชีหรือโอนเงินจริง

7. **ผลลัพธ์:** ระบบทบทวนความไม่ชัดเจนของเจ้าของเงินและการใช้บัญชีส่วนตัว อธิบายผลของสิ่งที่ผู้เล่นยืนยันจริง พร้อมแนะนำหยุดการส่งต่อและตรวจผ่านช่องทางที่เหมาะสม ไม่โยนความผิดจากยอดตั้งต้นให้ผู้เล่น

**จุดตัดสินใจหลัก**
- ตรวจหน้าที่และเจ้าของเงิน
- ปฏิเสธการใช้บัญชีส่วนตัวรับส่งเงินแทน
- ตรวจทานก่อนยืนยันการกระทำจำลอง

**เส้นทางหลัก: Safe / Review / Critical candidate**
- Safe: ปฏิเสธการให้ใช้บัญชีหรือส่งต่อ และตรวจหน้าที่ผ่านช่องทางอิสระ
- Review: ถือคำรับรองว่าบริษัทรับผิดชอบเป็นเหตุให้เชื่อโดยยังไม่ตรวจที่มาของเงิน
- Critical candidate: เลือกส่งต่อเงินของผู้อื่นผ่านบัญชีส่วนตัวและยืนยันจำลอง; ไม่ถือการอ่านงานหรือยอดตั้งต้นว่าเป็นการยินยอม

**ภาพสำคัญสำหรับ Storyboard**
- ประกาศงานและคำอธิบายหน้าที่
- แชตขอใช้บัญชีส่วนตัว
- รายการรับส่งเงินสมมติ
- ข้อมูลบริษัทและหน้าที่จากแหล่งอิสระ
- หน้าตรวจทานการส่งต่อเงินจำลอง
- หน้าผลลัพธ์

## Storyboard Drawing Checklist

- [ ] ชื่อและรหัสเรื่องตรง Story Bank; แสดงสถานะรอตรวจของเรื่องบนเอกสารคนวาด
- [ ] รู้ว่าผู้เล่นเป็นใคร เห็นอะไร และเลือกทำอะไรได้ตั้งแต่ต้น ไม่เฉลยด้วยชื่อเรื่องหรือสีเตือน
- [ ] วาดจากลำดับ 5–8 ขั้น ไม่บังคับให้ทุกทางเดินผ่านทุกภาพ; เรื่องสายปกติไม่ต้องมีการเร่งหรือข่มขู่
- [ ] เห็นการพิมพ์ตอบ การเลือกหลักฐานที่ควรตรวจ และการตรวจจากช่องทางอิสระ
- [ ] มีทางยุติตั้งแต่ช่วงต้นและกลับไปตรวจเอง ไม่ตีความว่าปิดหน้าต่างเท่ากับผ่าน
- [ ] เห็นความต่างของการถามเพิ่มกับการเชื่อหลักฐานที่ยังไม่เพียงพอ และสามารถกลับมาตรวจใหม่ได้
- [ ] ก่อนทำรายการเสี่ยงมีหน้าตรวจทาน ยืนยันการจำลอง และยกเลิก รวมการส่งสินค้า/เอกสารและการให้สิทธิ์
- [ ] ประวัติเงินหรือเหตุเสียหายที่เตรียมไว้ไม่ถูกนับเป็นการเลือกของผู้เล่น
- [ ] หน้าผลลัพธ์อธิบายสิ่งที่พบ การตัดสินใจ สัญญาณเตือน และสิ่งที่ควรตรวจต่อ ไม่ให้คะแนนตัวเลข
- [ ] สายปกติไม่มีคำขออันตรายที่แต่งเพิ่ม และสื่อว่าตรวจสอบอย่างสุภาพได้โดยไม่ปฏิเสธทุกสาย
- [ ] ไม่ทำลิงก์ QR แอป เอกสาร หรือรายการเงินให้ใช้งานจริง และไม่เปิดรับข้อมูลสำคัญจริง
- [ ] ตรวจรายละเอียดรายหมวดก่อนวาดทางเลือกย่อยหรืออนุมัติภาพฉบับสุดท้าย

| Story ID | Status | สิ่งที่ยังต้องทบทวน |
|---|---|---|

| [CC-N01](#cc-n01) | CONTROL / CONDITIONAL_CONTENT | อนุมัติบทสายจัดส่งปกติและแนวทางสะท้อนผลโดยไม่ลงโทษการตรวจสอบ |
| [CC-N02](#cc-n02) | CONTROL / CONDITIONAL_CONTENT | อนุมัติบทธนาคารแบบ matched control ข้อมูลอ้างอิง และแนวทางสะท้อนผลโดยไม่ลงโทษการตรวจเอง |
| [INV-01](#inv-01) | DEMO / NEEDS_CONTENT_REVIEW | แสดงประวัติทดลองและยอดเดิมให้ชัดว่าไม่ใช่การโอนของผู้เล่น |

| [ROM-02](#rom-02) | CORE / NEEDS_CONTENT_REVIEW | ทบทวนเอกสารของขวัญและบทของผู้ติดต่อสองคน ไม่เลียนเอกสารหน่วยงานจริง |
| [ECO-01](#eco-01) | DEMO / NEEDS_CONTENT_REVIEW | ยืนยันสินค้าและนโยบายคุ้มครองของแพลตฟอร์มสมมติ |
| [ECO-02](#eco-02) | CORE / NEEDS_CONTENT_REVIEW | ยืนยันความสัมพันธ์ของฉลากกับคำสั่งซื้อและเกณฑ์ผลจากการจ่ายปลายทาง |
| [ECO-03](#eco-03) | CORE / CONDITIONAL_CONTENT | อนุมัติบทผู้ขายและเกณฑ์ส่งมอบสินค้า แยกหลักฐานปลอมจากเงินเข้าล่าช้า |
| [PHI-01](#phi-01) | DEMO / NEEDS_CONTENT_REVIEW | ตรวจโดเมนสมมติและรายการหลักฐาน; QR เป็นทางเข้าแบบฟอร์มเดิม ไม่เพิ่มเรื่อง |
| [PHI-02](#phi-02) | CORE / NEEDS_CONTENT_REVIEW | ทบทวนสิทธิ์ที่ร้องขอและเกณฑ์แยกติดตั้งกับอนุญาต โดยคงเป็นหน้าจอจำลอง |
| [TASK-01](#task-01) | DEMO / NEEDS_CONTENT_REVIEW | ทบทวนภารกิจตัวอย่างและรายการค่าจ้าง แยกยอดสำรองเดิมจากการตัดสินใจผู้เล่น |
| [LOAN-01](#loan-01) | CORE / NEEDS_CONTENT_REVIEW | ยืนยันเงื่อนไขสินเชื่อและข้อมูลใบสมัครที่ตรวจได้จากช่องทางอิสระ |
| [LOAN-02](#loan-02) | DEMO / CONDITIONAL_CONTENT | แยกผู้ให้กู้ปลอมจากบริการที่ละเมิดข้อมูล อนุมัติขอบเขตรายชื่อและความรุนแรงของคำขู่ |
| [REC-01](#rec-01) | CORE / NEEDS_CONTENT_REVIEW | ทบทวนประวัติสูญเสียและเอกสารช่วยเหลือโดยไม่กล่าวโทษผู้เสียหาย |
| [REC-02](#rec-02) | DEMO / CONDITIONAL_CONTENT | ตรวจหลักฐานที่รองรับการผสมเรื่องช่วยเหยื่อเดิมกับแอปแจ้งความขอควบคุมเครื่อง และอนุมัติความต่างจาก PHI-02 |
| [JOB-01](#job-01) | DEMO / NEEDS_CONTENT_REVIEW | ยืนยันหน้าที่งานและนโยบายค่าใช้จ่ายขององค์กรสมมติ |
| [JOB-02](#job-02) | EXTENDED / CONDITIONAL_CONTENT | อนุมัติเรื่องเก็บข้อมูลโดยเฉพาะ รายการเอกสารที่จำเป็น และขอบเขตข้อมูลที่ถือว่าเสี่ยง |
| [JOB-03](#job-03) | CORE / NEEDS_CONTENT_REVIEW | แยกการยินยอมให้ใช้บัญชีกับการส่งต่อเงิน และยืนยันหน้าที่กับเจ้าของเงินสมมติ |

REC-02 ยังคง CONDITIONAL_CONTENT เพราะการเชื่อมเหตุช่วยผู้เสียหายกับการขอควบคุมเครื่องต้องตรวจความเฉพาะเจาะจงของแหล่งที่มา ไม่อ้างว่าบทผสมทั้งหมดเป็นเหตุการณ์ข่าวเดียว ส่วน CC-N01 และ CC-N02 ยังรอแนวทางสะท้อนผลของสายปกติ ไม่เติมความเสี่ยงเพื่อให้เหมือนเรื่องหลอกลวง
